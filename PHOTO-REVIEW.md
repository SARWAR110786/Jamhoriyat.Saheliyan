# Photo review — before launch

The brief (p.7) is unambiguous: real women, dignified framing, written consent
for every image, and captions that state **who, where and with what permission**.

Because the photographs in `../Photos` could not be inspected visually when the
site was assembled, the slot assignments below are **best guesses based on image
metadata** (orientation, face detection, brightness). Treat them as a starting
point, not as finished art direction.

---

## How to do this in 15 minutes

1. Run the site: `npm run dev`
2. Open **http://localhost:3000/photo-review**
3. You will see every slot the site uses, with its source file and current alt text.
4. For each one, open `src/content/photos.ts` and:
   - point `id` at a better file (any id from the grid at the bottom of that page)
   - rewrite `alt` so it describes what is **actually** in the frame
   - rewrite `caption` with who / where / permission
   - change `consent: false` → `consent: true` once consent is on file

Nothing should ship with `consent: false`.

---

## The full archive

**Every one of the 100 supplied photographs is now published** on `/gallery`
(and a rotating selection on the home page). Their alt text is deliberately
generic ("Photograph 12 from the Jamhooriyat Saheliyan archive…") because the
content of each frame is still unverified.

Before launch, the team should either:

- replace those generic descriptions with real ones in `src/content/gallery.ts`
  (regenerated by `scripts/build-gallery.py`), or
- remove any photograph from `/gallery` that does not have written consent.

The same consent rule applies to the archive as to the named slots: if consent
is not on file, the photo comes down.

## Caption formula

> *Who*, *where*, *with what permission* — and, where relevant, what she is doing.

Examples that meet the brief:

- “Nasreen, a member of the civic network in [Union Council], during a
  co-creation session. Photographed with written consent, [Month Year].”
- “Community session, [District]. Photographed with written consent.”

Examples that do **not** meet the brief:

- “Women empowerment.”
- “Beneficiaries of the programme.”
- Any caption that describes the tool doing something it cannot do yet.
